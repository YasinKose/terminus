# Terminus v0.2 — Scope design

**Date:** 2026-07-25  
**Status:** Approved product direction (post–v0.1 agent close)  
**Supersedes for new work:** this document + roadmap (does **not** rewrite frozen v0.1 design history)  
**v0.1 SoT (frozen core):** `docs/plans/2026-07-23-terminus-terminal-core-design.md`  
**Roadmap companion:** `docs/plans/2026-07-25-terminus-roadmap-v0.2-v0.3.md`

---

## 1. Relationship to v0.1

v0.1 delivered a **macOS-first local terminal workspace**:

`Project → Workspace → PaneNode (TerminalLeaf | SplitContainer)` with local PTY,
SQLite layout persistence, profiles, activity/OSC, palette/shortcuts, six
presets, and local unsigned `.app`/`.dmg`.

v0.1 design **explicitly excluded** (verbatim themes from design §1):

1. VDS/VPS and remote execution  
2. SSH  
3. tmux or a custom background daemon  
4. AI agent orchestration and chat  
5. Git UI  
6. Tasks, snippets, Makefile import, and editor surfaces  
7. Signing, notarization, updater, and Homebrew distribution  

**v0.2 moves a controlled subset of those exclusions into scope.** Everything else stays parked in v0.3+.

v0.1 **invariants that v0.2 must not break:**

- Leaf `id` === PTY session id; layout ops preserve leaf identity  
- High-frequency PTY output never through Zustand  
- Rust owns OS side effects; typed Tauri commands; structured errors  
- Profile-validated spawn only (no free-form shell executor from UI)  
- Parameterized SQL; least-privilege capabilities  
- App restart restores layout with **new** shells unless a documented
  **optional** tmux-attach path says otherwise  
- Closing final pane does not delete the workspace  

---

## 2. v0.2 product intent (one sentence)

Make Terminus a **multi-OS daily terminal workspace** with **light project tools**
(Git UI, tasks, snippets) and an **optional tmux bridge**, without becoming an
IDE, remote orchestrator, AI surface, or signed distribution product.

---

## 3. In scope for v0.2

### 3.1 Multi-OS runtime

**Goal:** Run and package Terminus on **macOS, Linux, and Windows** with honest
platform differences—not full store-ready distribution polish.

| Area | Direction |
|------|-----------|
| Shell resolution | Platform module: login-shell / default shell / Windows shells; no hard-coded `/bin/zsh` as sole path |
| Window chrome | Abstract macOS traffic-light/titlebar overlay; Linux/Windows native chrome variants |
| PTY / process | Portable-pty + platform process-group kill semantics |
| Packaging | Local installers per OS where Tauri supports them; CI matrix later |
| Perf gates | Keep M2 macOS numbers as primary; add platform notes, not fake universal numbers |

**Out of multi-OS v0.2:** notarization, code signing as product requirement,
Homebrew/apt/chocolatey channels, auto-updater.

### 3.2 Git UI (light workbench)

**Goal:** Project-scoped Git status and common local operations beside the
terminal—not a full GitHub/GitLab IDE.

**Must set (v0.2):**

- Status (dirty files, branch, ahead/behind when cheap)  
- Diff view (file-level)  
- Stage / unstage / commit  
- Branch list / checkout / create (local)  
- Stash (basic)  

**Rules:**

- Backend in Rust (prefer libgit2/`git2` or equivalent structured API)—**not**
  free-form `git` shell from the frontend  
- Capabilities remain least-privilege (project tree / `.git` only as needed)  
- Removing a Terminus project never deletes or rewrites the git repo on disk  
- Low-frequency polling only; never piggyback on PTY byte path  

**Defer:** PR review suite, remotes hosting UI, conflict merge editor, submodule
deep tools, worktree manager mega-features (may land later if designed).

### 3.3 Tasks

**Goal:** Project-scoped task board (legacy behavioral reference: project-local
board file such as `.tasks/board.json`—re-specify in implementation plan).

**Must set:**

- CRUD columns/cards  
- Persist per project (files preferred over SQLite layout DB unless migration justified)  
- Open from shell/palette without auto-spawning shells  

**Must not:**

- Silent startup task runner that spawns PTYs without profile validation  
- Replace the terminal as the primary work surface  

### 3.4 Snippets (+ optional Makefile import)

**Goal:** Snippet library with insert into the **focused** PTY via existing
`write_pty` path.

**Must set:**

- List / create / edit / delete snippets  
- Insert into focused session  
- Optional Makefile target discovery (read-only parse) as import source  

**Must not:**

- Full editor surface / IDE buffer  
- Second shell executor  
- Unscoped filesystem writes outside project/config roots  

### 3.5 tmux bridge (opt-in)

**Goal:** Optional attach/control path to the **user’s** tmux—not Terminus
becoming a background daemon or replacing local PTY as default.

**Must set:**

- Detect/list tmux sessions (when tmux available)  
- Attach / open as a first-class session backend alternative  
- Clear UX: local PTY vs tmux-attached (reconnect semantics documented)  
- Honest restart story: what survives app quit vs what does not  

**Must not:**

- Replace SessionManager default path silently  
- Claim process/scrollback restore for pure local PTYs  
- Ship a custom long-lived Terminus daemon as a substitute for tmux  

**Gray line (state in implementation plan):** control-mode client lifecycle is
allowed; a Terminus-owned always-on mux daemon is **v0.3+ / never** unless
separately designed.

## 4. Explicit non-goals for v0.2 (park → v0.3+)

| Item | Why |
|------|-----|
| SSH / remote execution / VDS-VPS | Different trust & network model |
| AI agent orchestration / chat | Conflicts with “not agent IDE” |
| Custom Terminus background daemon (product) | Distinct from tmux bridge |
| Signing, notarization | Distribution maturity |
| Auto-updater | Distribution |
| Homebrew / multi-channel polish | Distribution |
| Plugin marketplace | Security surface |
| Editor surfaces / embedded browser | IDE pivot |
| Serial / SFTP / quake mode | Peer-deferred niches |
| Encrypted secret store | Profile env stays local plaintext config |
| Profile marketplace / icon system / inheritance | Design micro-exclusions |
| Full conditional keymaps / JSON keybinding files | Design §11 |
| Arbitrary color editor | Design §11 |
| Process revive + scrollback for local PTY across restart | Design §5 (except documented tmux path) |
| Foreground-process inspection / shell injection | Design §8 |
| Fleet / mobile / agent-native | legacy vision only |

## 5. Suggested module boundaries

```text
src/features/
  git/
  tasks/
  snippets/
  tmux/                 # bridge UI / status / attach

src-tauri/src/
  platform/             # multi-OS shell, paths, window policy
  git/                  # structured git backend
  tmux/                 # client/bridge (or pty/backends/)
```

**Shared rules:**

1. Rust owns OS side effects.  
2. Typed commands + structured `ErrorPayload`.  
3. Least-privilege capability growth only.  
4. Separate Zustand stores (low frequency).  
5. Pane tree / TerminalRuntimeRegistry / SessionManager remain SoT for local terminals.  
6. No imports from `legacy/` code (behavior docs only).  
7. New tracks get dated implementation plans under `docs/plans/`—do not silently
   rewrite the frozen v0.1 design file.

---

## 6. Security spine (unchanged)

- Profile-validated spawn only  
- Parameterized SQL  
- PTY/OSC data untrusted  
- No free-form shell executor for Git/tasks/snippets  
- Capability review on every module  

---

## 7. Success criteria (v0.2 DoD sketch)

1. Multi-OS: builds and basic open-project → shell on macOS + at least one of
   Linux/Windows in CI or documented local proof.  
2. Git light workbench usable on an open project without shell hacks.  
3. Tasks board persists per project and survives app restart.  
4. Snippet insert reaches focused PTY.  
5. tmux bridge optional; default local PTY path still primary and tested.  
6. No v0.3 items (SSH/AI/signing/updater) merged.  
7. Automated gates extended (`verify:v01` → versioned verify script as needed).  
8. Human smoke matrix extended for new surfaces.  

Detailed tasks belong in a future `docs/plans/YYYY-MM-DD-terminus-v0.2-implementation.md`.
