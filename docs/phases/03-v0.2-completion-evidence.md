## 2. Hardening evidence

- Git checkout uses safe checkout and rejects non-local-branch revisions.
- Project Git lookup does not discover a repository above the registered root.
- Untracked file diffs include textual content.
- Git file rows open a transient read-only Source Lens while preserving the
  mounted terminal workspace; preview, diff, and stage/unstage are distinct
  actions.
- Source previews reject absolute/escaping paths, external symlink targets,
  binary or non-UTF-8 content, directories, and files larger than 2 MiB.
- Deleted working-tree files may be previewed from their HEAD blob without
  adding a broad filesystem or shell capability.
- Source Lens language support is lazy-loaded and uses the Terminus semantic
  theme, visible keyboard focus, reduced-motion fallbacks, and responsive
  source metadata.
- Git commits and stashes require configured `user.name` and `user.email`.
- Git/task/snippet stores ignore stale responses after project changes and
  clear project-scoped UI state before accepting new actions.
- Git/task/snippet refreshes cannot overwrite newer same-project mutations or
  file-diff state.
- Git/task/snippet mutations are serialized with visible busy states.
- Task-board mutations are rejected and their controls disabled while the
  current project board is loading.
- Git status refreshes on window focus and a low-frequency 30-second interval,
  only while its panel is open, visible, and no status, mutation, or diff
  request is active.
- Same-project Git refreshes preserve completed patches, file switches clear
  stale patch content, and diff filenames use literal path matching.
- Partial shortcut preferences preserve the active OS defaults.
- Windows profile resolution ignores Unix-style captured `SHELL` values.
- Imported Makefile targets reject shell metacharacters.
- Project data and Makefile reads reject symlink escapes.
- Destructive task/snippet actions require confirmation.
- v0.2 panels are lazy-loaded and share a responsive, keyboard-accessible
  workbench shell.
- The root `Makefile` exposes documented daily development and complete CI
  orchestration targets; `make help` and `make -n ci` pass.
